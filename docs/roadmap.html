Our own way of doing the job

Three ideas the app is built around

The checks read the file

Every check runs on the finished PDF, not on the settings, so nothing passes on a promise. A broken rule shows on the page it's on.

The page is looked after

Sentences kept whole across page turns, every full page ending on the same line, and a pinned page count so the cover still fits.

The spine follows the book

The cover is sized from the real page count and paper, and resizes and tells you when the book changes.

1.0Interiors for KDPPlanned19 items

🙋 A whole book laid out for KDP paperback and hardcover, checked, and ready to upload. Story Tracker, refresh, and only that page moves. The menus, Help, About and Preferences use RT Markdown Reader's wording, and every theme passes the contrast test. The print preview and the layout screens have their own design, inside that frame.

Bring in a book

You askedM

From RT Story Tracker in one step, or from Word, Markdown or EPUB files. A Story Tracker book stays read-only here; a book that came from files can have its words corrected here.

Every KDP trim size

You askedS

All 16 paperback sizes, custom paperback sizes inside KDP's limits, and the 5 hardcover sizes, with or without bleed.

Margins from the page count

You askedS

Mirrored margins, the inside margin set from the real page count, and the outside, top and bottom never under KDP's minimum.

Book themes

You askedL

A starter set of book themes (the design of the printed pages, not the window's colours), each with fonts for titles, subtitles and body, sizes, spacing, drop caps, scene breaks, chapter openers and folios. Change anything and save it as your own.

Front and back matter

You askedM

Title, copyright, dedication, acknowledgements, contents, a note to the reader, Parts, prologue, epilogue, appendices, a preview of the next book, also by, and stay connected, in the order you choose.

Titles on the right

You askedS

Every title in the contents starts on a right-hand page, with a blank before it when needed.

Running heads

You askedS

The author's name on left-hand pages and the book's title on right-hand pages, or the chapter's title instead, on or off in each book theme. None on chapter openers, Part pages or blank pages.

Page turns

You askedL

No sentence split across a page turn, unless it's on your list of turns kept for suspense. A report lists what moved and anything that couldn't.

Even page bottoms

You askedM

The text block holds a whole number of lines, and every full page ends on the same bottom line.

Pin the page count

You askedS

Keep the published page count so an existing cover still fits, and end on a blank page with an even total.

Fonts you can trust

You askedS

Bundled fonts plus any on the computer that allow embedding. A character missing from its font stops the build, so nothing falls back to another font.

Language and hyphenation

You askedS

The book's language sets hyphenation and the quotation style, and hyphenation can be turned off. No hyphenated word is split across a page turn.

Checks before upload

You askedM

KDP's rules for trim, page count, margins, bleed, fonts, picture resolution, links and blank pages. A broken rule is shown on the page it's on, and the file isn't written until it's fixed.

Preview

M

The pages as they'll print, side by side as spreads, updating as you change the theme.

Installed list

S

On first run and after each update, writes installed/rt-press.json (id, name, version, launch path, protocol) in the App Link folder, and removes it on uninstall, so the other apps can find Press.

Menus and Help

You askedM

File, Edit, View and Help, each kept short, with less-used commands in submenus and every command runnable by name from the command palette (Ctrl+K). The Help menu in the suite's order: *Help Center* (F1), *Tutorial*, *Check for Updates…*, *About RT Press*. Guides are plain Markdown files in a help folder, and the tutorial offers a practice book.

About and Preferences

You askedS

The suite's About window: icon, version, *Website*, *What's new in this version*, *Report a problem or suggest a feature*, *Source code*, the Electron, Chromium, Node and system versions with *Copy details*, and links to the licence and the open-source notices. One Preferences window (Ctrl+,) holds every setting.

App themes and the toolbar

You askedM

The window is built to the suite's [theming file](https://github.com/neogentrics/rt-markdown-reader/blob/main/docs/app-theming.md), taken in from the suite's one shared themes file in the private repo neogentrics/recon-theme, not copied by hand: a script copies the files at a pinned tag and writes a theme.lock (a hash of them), Press commits both, so building never needs access, and a test fails if the copy differs from the lock (the files move in after RT Markdown Reader's 3.13.x look update merges, and until then RT Markdown Reader's files are the source): the ten shared themes (Paper, Night, Sepia, Mist, Forest, Dusk, Blue, Red, Yellow, High Contrast) plus *Auto*, the shared colour tokens, the *Solid*, *Metallic* and *Glass* looks, *Colour-safe* and *Customize Theme*. A theme made in *Customize Theme* or loaded from a file is kept once in the suite's shared folder, so every app offers it, and a theme that fails contrast is refused. One theme button on the main screen, also under *Preferences → Appearance* and *View → Look*. Contrast of every theme with every look is measured in the tests on all three systems. The page preview stays plain, since looks are for the window around it. An icon toolbar with a name on hover for each button.

Updates, access and languages

You askedM

*Restart to update* where the system allows it, and a download link where it doesn't. Every button named, every theme at WCAG AA contrast, Windows high contrast, and everything doable from the keyboard, all checked by the tests. Spanish, French and German, and right-to-left layouts.

Test: lay out a book in each trim size, upload it to KDP's previewer, and it reports nothing. Change one word in RT

Decisions

11 chosen by you, 5 defaults approved with the plan, 2 waiting for you

Should apps follow each other's theme?

Changing the theme in one app would switch the linked apps too. It needs a small addition to App Link, so a protocol decision, made together with kinds. Nothing starts before you say go.

Should hello also return kinds?

The suite proposes that every app says which document kinds it does something with, so a sender only offers an action the other app handles. It changes the App Link protocol for every app, so it needs your yes. Press builds nothing for it until you say yes, and then only in v1.7.

KDP rules are hard rules

Trim, page count, margins, bleed and file rules can't be switched off. Your house rules are a preset: on for you, offered to everyone.

Fonts

Bundled open-licence fonts, plus any on the computer that allow embedding. A missing character stops the build.

A book arrives as one file

An .rtbook file, by App Link or by opening it, so App Link needs no change. A locked project is never sent.

Your existing themes

Brought over by a private one-time converter, kept out of the repo, because they name your books.

The step-zero book

One of your finished books, chosen with you at the start of step zero.

Chosen by you

Which app keeps which export

Press does all of it, for authors who don't use the other apps: designed interiors and covers, plus EPUB, Word and plain formats from v1.6. The three apps share one piece of export code instead of three copies.

How the pages are set

An open typesetter, Typst, ships inside the app. Step zero proves it can match your build script before v1.0 starts.

Where the words live

One home for the text. A book from RT Story Tracker is read-only here, with a jump to the chapter; a book brought in from files can be corrected here.

How far the covers go

Size, place and set type. A template for your illustrator, the art placed, the type set and checked. No painting tools.

What 1.0 does

Interiors for KDP first. Frames in 1.1, art in 1.2, covers in 1.3 and 1.4, where Press replaces your build script.
